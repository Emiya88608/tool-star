# Bad Case 分析

本文档记录统一评测与人工复核中最具代表性的错误类型。所有索引均对应 98 题调试保留集。

## 1. 几何关系理解错误

### Index 9：把线性对误当成对应角

- 题目：直线上的相邻角为 `x + 26°` 与 `2x + 10°`。
- 标准答案：`48°`。
- SFT：将两个角设为相等，得到 `16`。
- GRPO：正确使用和为 `180°` 的线性对关系，得到 `48`。

**启示：** 模型会复用“对应角相等”这类常见几何模板，即使图形条件不支持。训练或奖励中可加入“关系选择”和“方程验证”检查。

### Index 41：图形坐标与面积建模

- 标准答案：`18`。
- SFT：面积计算中多除了一次 2，输出 `9`。
- GRPO：中间坐标解释不严谨，但最终以底 `9`、高 `4` 得到正确面积 `18`。

**启示：** 最终答案正确不代表轨迹可靠。几何任务应额外记录建模过程是否满足图形约束。

## 2. 工具输出与文字推理不一致

### Index 13：集合计数

- 标准答案：`6`。
- SFT：Python 中错误的容斥代码返回 `-6`，文字却忽略工具结果并输出 `8`。
- GRPO：文字中的集合解释仍有错误，但 Python 的逐项判断返回 `6`，最终答案正确。

**启示：** 当前工具协议允许模型在工具报错或结果异常后继续编造结论。后续可对“最终答案是否与最后一次 Python 结果一致”增加奖励或约束。

### Index 21：代数化简与标签协议

- 标准答案：`4a-2`。
- SFT：把常数项 `1-2+3-4` 误算为 `0`，输出 `4a`。
- GRPO：最终用 SymPy 得到 `4a-2`，但轨迹出现重复/嵌套的答案标签。

**启示：** 需要把“数学正确性”和“工具/标签协议正确性”分别度量。

## 3. 计数边界与 off-by-one

### Index 53：24 小时同步备份次数

- 标准答案：`144`。
- SFT：从第 10 分钟起计数，得到 `144`。
- GRPO：循环包含 `t=0`，把起始时刻额外计入，输出 `145`。

### Index 93：前 N 个正倍数

- 标准答案：`10`。
- SFT：正确列出 `6,12,...,60`。
- GRPO：用 `range(10)` 生成了 `0,6,...,54`，漏掉 `60`，输出 `9`。

**启示：** GRPO Pilot 的典型错误是把自然语言中的“前 N 个正数”转成零起始代码。训练样例应加入明确的边界测试和程序断言。

## 4. 公式迁移错误

### Index 38：三个数的最小公倍数

- 标准答案：`1020`。
- SFT：最终调用正确的两两 LCM 函数，输出 `1020`。
- GRPO：使用不适用于此处的三数 GCD 乘积公式，输出 `60`。

**启示：** 模型会将二元公式错误泛化为多元公式。对工具使用的奖励不应只看是否调用 Python，还应检查最终数值。

## 5. 语义正确但严格格式失分

| 索引 | 模型 | 数学答案 | 严格评分为何失败 |
| --- | --- | --- | --- |
| 74 | SFT | `1 1/4` | 最终答案为自然语言句子，未形成可解析的精确表达式 |
| 75 | SFT | `-40/153` | 同上 |
| 91 | GRPO | `-1` | `<answer>` 内是完整句子，未输出独立的可解析结果 |

**启示：** 报告中需同时提供严格协议评分与人工语义复核；训练中可在末尾专门增加“仅输出 `\\boxed{...}`”的格式奖励。

## 建议的后续改进

1. 将 Python 返回值与最终答案做一致性校验，降低工具结果被忽略的概率。
2. 增加边界与计数类训练样本，尤其覆盖“从 1 开始”“不包括起始时刻”等条件。
3. 将最终答案的可解析格式独立奖励，且与数学正确性分开记录。
4. 在全新盲测集上测试改动，避免调试集带来的乐观偏差。
