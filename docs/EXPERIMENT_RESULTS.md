# 实验结果与审计说明

## 1. 比较目标

比较 Base、数学工具轨迹 SFT 与 GRPO Pilot 在同一数学工具推理任务上的表现。所有组共享相同的评测题、系统提示词、解码设置和 Python 工具执行流程。

| 组别 | 模型来源 | 训练状态 |
| --- | --- | --- |
| Base | Qwen2.5-1.5B-Instruct | 未进行本项目的后训练 |
| SFT | Base + 5k 数学工具轨迹 LoRA | 已合并 LoRA 权重 |
| GRPO Pilot | SFT + GRPO | 128 条样本、32 训练步、修复后的奖励函数 |

## 2. 数据与泄漏审计

- SFT 数学训练集：5,000 条，归一化后 4,998 条唯一问题。
- 最初的 100 题评测中，有 2 题与 SFT 训练问题完全重合。
- 这 2 题已被移除，形成 98 题统一评测集合。
- GRPO Pilot 训练集与该 98 题集合按 NFKC 与空白归一化后的题目文本比对，重合数为 0。

这消除了已知的训练题直接重合，但 98 题集仍被用于提示词和评分器调试，因此报告中统一称为“调试保留集”。

## 3. 统一评测配置

| 维度 | 配置 |
| --- | --- |
| 提示词 | SFT 训练所用工具协议提示词 |
| 温度 | 0 |
| 单轮最大生成长度 | 2048 tokens |
| 最大上下文长度 | 8192 tokens |
| Python 工具调用上限 | 3 次 |
| 执行器 | 真实 PythonExecutor；工具结果写回后继续生成 |
| 推理服务 | vLLM，逐题批处理 |
| 评分 | 修复后的数学等价判定 + `<answer>` 协议检查 |

## 4. 严格自动评分结果

| 模型 | 正确数 | 自动正确率 | 缺失最终输出 | 含 `<answer>` 的输出 |
| --- | ---: | ---: | ---: | ---: |
| Base | 28 / 98 | 28.57% | 38 | 21 |
| SFT | 58 / 98 | 59.18% | 2 | 88 |
| GRPO Pilot | 59 / 98 | 60.20% | 0 | 93 |

### 可直接得出的结论

1. SFT 相对 Base 的提升明显：自动正确率增加 30.61 个百分点，缺失最终输出由 38 降至 2。
2. GRPO Pilot 将缺失最终输出进一步降至 0，表明其输出协议完成率更高。
3. SFT 与 GRPO 的 1 题自动正确率差异不足以单独支持“GRPO 提升数学准确率”的结论。

## 5. 奖励函数修复

原始数学等价逻辑会出现如下风险：

- 将 `4a` 与 `4a-2` 误判为相等；
- 将 `4a` 与 `4b` 误判为相等；
- 对空答案或缺失答案给出错误的正向判定。

修复后使用完整表达式和变量一致性检查，并验证了 17 个回归用例：正确/错误多项式、大小写变量、分数、小数、负数、区间边界、空答案和嵌套工具标签。全部通过后才用于 GRPO Pilot。

## 6. SFT 与 GRPO 分歧人工复核

严格自动评分的分歧数：

| 类别 | 数量 |
| --- | ---: |
| GRPO 相对 SFT 新增正确 | 10 |
| GRPO 相对 SFT 回退 | 9 |

人工复核 19 个分歧后：

| 人工分类 | 数量 | 索引 |
| --- | ---: | --- |
| GRPO 真实新增正确 | 8 | 9, 13, 21, 33, 41, 84, 85, 92 |
| GRPO 真实回退 | 8 | 7, 20, 24, 34, 38, 53, 76, 93 |
| 仅最终答案格式导致的自动评分差异 | 3 | 74, 75, 91 |

人工复核说明：Index 74 和 75 中，SFT 的自然语言最终答案在数学上正确，但未被严格答案提取器解析；Index 91 中，GRPO 的 `x=-1` 在数学上正确，但最终输出是句子而非可直接解析的精确表达式。

**结论：** 在人工复核的全部分歧案例中，GRPO 对 SFT 的数学语义正确性净变化为 0。严格自动评分的 `59/98` 与 `58/98` 主要反映最终答案可解析性差异。

## 7. 复现边界与下一步

- GRPO 训练规模为 Pilot，不应外推为大规模 RL 的最终效果。
- 98 题集不是新鲜盲测集。
- 下一次实验应采用未参与调试的 50–100 题盲测集，并扩大 GRPO 数据量、训练步数和随机种子数。
